L'app UWP de 2016 ne vivait que par le Windows Store ; son frontend (Template10, SQLite.Net-PCL, Toolkit 1.2) est mort avec lui, pendant que Renovate arrosait un webservice netcoreapp1.0 jamais branché au frontend. La vraie source de données — un SQLite veekun de 49 Mo interrogé par 15 requêtes SQL artisanales — est conservée telle quelle : un générateur exécute les requêtes de 2014 verbatim et matérialise une API statique JSON que la réécriture Blazor consomme. Les 721 Pokémon (799 formes), méga-évolutions et formes alternatives se consultent en français, en ligne et hors ligne, dans deux thèmes : « Rubis » (clair, l'accent rouge sombre de 2016) et « Saphir » (nuit).

Valeur business

Ce que cette migration change concrètement.

  • L'app revit sur tous les appareils. Distribution Windows Store morte → PWA web : 721 espèces, 48 méga-évolutions, table des types, capsules techniques — installable, consultable hors ligne (contrat de l'app installée de 2016 : données et icônes préchargées).
  • La donnée et l'art de 2016 sont conservés octet pour octet. Le SQLite veekun n'est pas réinterprété : les 15 requêtes SQL de 2014 s'exécutent verbatim au build ; 2 713 illustrations, icônes et la police embarquée sont copiées telles quelles.
  • Le comportement est prouvé, quirks compris. 53 tests figent les requêtes (799 formes, matrice 18×18, CT), les formats (« 5'6" (1.70 m) »), les suffixes de formes (#006MX, #201!) et jusqu'aux bizarreries de la recherche de 2016.
  • L'audit initial est corrigé. Le « backend moderne à conserver » n'existait pas (netcoreapp1.0 + SQL Server jamais branché) et le « projet de tests » était une référence pendante. La mise à jour automatique de dépendances maquillait un projet mort — leçon codifiée dans le kit.

Le Pokédex, thème « Rubis » : bandeau rouge sombre et police de 2016, tri par familles d'évolution, pastilles aux couleurs officielles des types (encres mesurées AA). Fiche, galerie « Saphir », matrice des types et preuve hors-ligne dans captures/.

Suivis différés

  • Actualité (NewsPage) — l'app interrogeait l'API Bing News (service et SDK morts) — page non portée ; à remplacer par une vraie source si souhaitée en v2.
  • Games (page vide) — coquille sans contenu ni ViewModel dans l'app de 2016 — non portée.
  • Textes des talents — la fiche 2016 affichait l'effet détaillé en anglais (seconde pile EF, non portée) ; la fiche affiche le texte français du jeu — divergence assumée, plus cohérente avec l'app.
  • Évolutions tripliquées — la requête legacy renvoie chaque évolution 3× (fan-out de jointure) — figé par les tests ; l'UI dédoublonne à l'affichage (l'app 2016 affichait bien Salamèche trois fois).
  • Illustrations hors ligne — données et icônes sont préchargées ; les grandes illustrations (25 Mo) se mettent en cache à la visite — nuance assumée pour ne pas imposer le téléchargement.
  • Poids des assets — JPG/PNG de 2016 repris tels quels par fidélité ; version WebP/AVIF possible en v2.
